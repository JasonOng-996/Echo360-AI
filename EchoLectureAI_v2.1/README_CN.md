# EchoLecture AI 2.1.0 源码测试版

从 Echo360 下载账户允许下载的 MP4 和 VTT，分析关键画面，再结合字幕生成学习笔记。默认使用 OpenAI，保留 Anthropic 选项，模型 ID 可自行填写。

本包包含源码、Windows 启动脚本和安装包构建流程。最终 Windows EXE 尚未在本次环境中编译或验收。

## 开始使用

1. 将整个压缩包解压到一个新目录。
2. 双击 `run_app.bat`。首次运行会创建 Python 环境并联网安装依赖；找不到 Python 时会尝试通过 winget 安装 Python 3.12。安装失败时命令窗口会保留错误信息。
3. 点击“导入旧版设置”，选择原来包含 `config.json` 和 `.env` 的文件夹，例如你正在使用的 `UQ_Echo_AI_v1.2.2_courses_openai`。API Key 和旧输出目录会一起导入；原来的视频不用移动。已使用 App 2.0 的用户会继续读取本机的 App 设置。
4. 在“AI 与抽帧”选择 `openai`，核对模型 ID 和 Key，点击“测试 API”。默认模型 ID 沿用分享记录中的设置，是否可用以你账户的实际测试为准。
5. 点击“下载并分析课程”。在 Edge 完成 UQ 登录和 MFA，通过 Learn.UQ 打开一次 Lecture Recordings，再返回 App 点击“登录后继续”。
6. 已经下载视频和字幕时，可以直接使用“分析已下载文件”。

UQ 常用设置：

| 设置 | 值 |
| --- | --- |
| 学校登录网址 | `https://portal.my.uq.edu.au/` |
| Echo360 Courses | `https://echo360.net.au/courses`，也可填你自己的 Courses 链接 |
| 学期 | `2026S2` |
| 课程选择 | `all` 为全部；`prompt` 在扫描后选择课程编号 |
| 总帧数上限 | `0` 表示不限总帧数，仍按关键内容筛选 |
| 每门课最多处理 | `0` 为全部；`1` 可用于首次验收 |

## 2.1 修复与行为

- 修复 App 2.0 保存设置时无限递归的问题，写入设置前保留 `config.json.bak`。
- MP4 和 VTT 使用独立标签页下载。主课程列表保留，失败不会退回主列表继续冒险点击。
- 浏览器下载保存失败时，尝试使用该次下载提供的原始 URL 和当前登录会话流式下载；完整浏览器会话已经关闭时仍可能需要重新登录。
- 下载先写临时文件，验证 MP4 容器边界或 VTT 格式，通过后才替换正式文件。HTML 登录页、空文件和部分下载不能算成功。
- 每节课的下载最多尝试两次，失败后记录状态并继续后面的课程。重新运行会再次处理未完成项目，不是从视频的某个字节位置续传。
- 按输入文件、模型、提示词和抽帧参数识别可复用结果；视觉分析按批次保存，中断后可复用完成批次。
- AI 返回空内容、输出被截断或视觉分析失败时，不会把整节课标记完成。选中画面分析时，总结会等待画面分析成功。
- 增加停止任务、阶段进度、导入旧设置和导出已脱敏日志。停止期间不会提交新的分析批次；正在进行的 API 请求需等待结束或超时，仍可能产生该次请求的费用。
- 同一天、不同完整标题的课堂使用不同子目录，避免按日期覆盖。无法唯一匹配的课堂会报错并跳过。

## 旧分析结果的处理

旧版没有记录缓存与输入的对应关系。首次用 2.1 分析旧数据时，AI 分析可能重新调用 API。新结果成功写入前保留旧结果，成功后旧最终笔记保留为 `summary.previous.md` / `visual_analysis.previous.md`。此前的 MP4 和有效 VTT 会直接复用。

如果以后修改帧数、模型、字幕或提示词，直接重新运行；不要为了重跑而删除已经下载的 MP4。重跑后可以看日志中的 `Reusing`、`Analyzed batch` 和 `[RESULT]` 确认复用情况。

## 输出文件

| 文件 | 用途 |
| --- | --- |
| `lecture_lower.mp4` | 验证通过的课堂视频 |
| `transcript.vtt` | 带时间戳的字幕 |
| `video_frames/` | 按本次分析参数区分的关键帧 |
| `visual_manifest.md` | 画面和字幕时间索引 |
| `visual_analysis_parts/` | 可复用的视觉分析批次 |
| `visual_analysis.md` | 画面分析结果 |
| `summary.md` | 最终课堂笔记 |
| `*.cache.json` | 输入指纹及输出校验值 |
| `status.json` / `done.json` | 当前阶段、失败原因与完成状态 |
| 课程根目录的 `last_run.json` | 本次多课程处理结果 |

## 首次 Windows 验收

建议先把“课程选择”设为 `prompt`，每门课最多处理设为 `1`，选择之前报错的 INFS2200，观察 2026-07-29 这节课。

核对保存设置、API 测试、登录后继续、MP4/VTT 下载，以及最终两个 Markdown 文件。再运行一次，确认复用已有结果；任务中点击停止，然后再次运行，确认可以继续处理。完成后将处理上限改回 `0`。

当前实现沿用你的 UQ Echo360 页面选择规则；其他学校、语言界面、分页或虚拟滚动列表仍需实际验证。

## 构建可分发的 EXE

在 Windows 双击 `build_windows.bat`，它会安装构建依赖、运行测试、构建程序并执行已打包程序的启动检查。成功后得到 `dist/EchoLectureAI/EchoLectureAI.exe`。

安装 Inno Setup 6 后运行 `build_installer.bat`，预期输出为 `release/EchoLectureAI-Setup-2.1.0.exe`。这些是构建目标文件名，不是本包已经提供的文件。

项目附有 GitHub Actions 流程。上传到自己的仓库后可以手动运行 `Build Windows App`；创建版本 tag 时会准备一个 Release 草稿。测试、安装包和 SHA-256 结果可在 Actions 的产物中下载。

## 验证范围

本次环境执行了离线回归测试和真实 FFmpeg 抽帧。浏览器与 AI SDK 调用在回归测试中使用模拟对象，未使用你的账号或 API Key。Windows GUI、真实 Echo360 下载、真实 API 和 EXE 安装仍需在 Windows 完成验收，详见 `VALIDATION.md`。
